# React App

Универсальная заготовка перед хакатоном: React Native, Expo SDK 57, React 19 и TypeScript. Один проект для Android, iOS и браузера. Конкретная тема и бизнес-логика ещё не выбраны.

## Быстрый запуск

На этом компьютере проект находится в `F:\React_App`. Node.js 24 LTS и npm установлены в `F:\DevTools\node-v24.22.2-win-x64` и добавлены в пользовательский PATH. Откройте новый терминал после установки.

Для браузера дважды нажмите `start-web.cmd`. Для телефона запустите `start-mobile.cmd`, установите Expo Go и отсканируйте QR-код в терминале. Компьютер и телефон должны быть в одной сети. Если локальная сеть блокирует соединение, проверьте точку доступа телефона; режим tunnel требует интернета и дополнительного пакета.

```powershell
cd F:\React_App
npm.cmd run web
# Или QR-код для Expo Go:
npm.cmd start
```

В другом клоне сначала выполните `npm.cmd ci`. На macOS/Linux используйте `npm` вместо `npm.cmd`.

SDK 57 выбран по совместимости Expo Go на 10 ноября 2026 года. Не обновляйте Expo отдельно от совместимых React Native и React. Новые пакеты добавляйте через `npx.cmd expo install имя-пакета`.

## Что уже работает

- Главная, каталог примеров, отдельная карточка и экран неизвестного адреса.
- Поиск по названию и категории, фильтр избранного и пустое состояние.
- Избранное сохраняется локально между запусками через AsyncStorage.
- Общие кнопки, карточки, адаптивная разметка и единая тема.
- Необязательный клиент API с таймаутом и обработкой HTTP-ошибок.
- Строгая проверка TypeScript, ESLint, сборка веб-версии и Android JS-бандла.
- GitHub Actions запускает проверки при push и pull request.

Примеры не требуют внешнего сервера или загружаемых шрифтов. Это не готовая задача хакатона. Сервер, авторизация, общая база данных и ИИ пока не подключены. AsyncStorage хранит только демонстрационные идентификаторы избранного на текущем устройстве, без синхронизации между участниками.

## Структура

```text
src/
  app/                 Экраны и маршруты Expo Router
    index.tsx          Главная
    demo/index.tsx     Каталог с поиском
    demo/[id].tsx      Карточка
    +not-found.tsx     Неизвестный адрес
  components/          Общие элементы интерфейса
  features/demo/       Демонстрационные данные и избранное
  lib/api.ts           Необязательный HTTP-клиент
  theme/               Цвета интерфейса
docs/
  HACKATHON.md          Выжимка из присланных материалов
  ENVIRONMENT.md        Проверенная среда и границы проверки
```

## Начало работы после получения задания

1. Определите один законченный сценарий и распределите работу.
2. Замените `src/features/demo/data.ts` данными организаторов; переименуйте демонстрационные экраны под задачу.
3. Подправьте общие цвета и компоненты. Название, slug и идентификатор Android находятся в `app.json`.
4. При необходимости подключите сервер через `src/lib/api.ts`. Перед использованием проверяйте структуру полученных данных в коде своей функции.
5. Пройдите сценарий на устройстве для показа и подготовьте защиту.

Для сервера скопируйте `.env.example` в `.env`, укажите `EXPO_PUBLIC_API_URL` и перезапустите Expo. На телефоне `localhost` означает сам телефон: нужен доступный адрес компьютера или размещённого сервера. Для браузера сервер должен разрешать соответствующий origin через CORS. Все `EXPO_PUBLIC_*` значения видны пользователям; закрытые ключи ИИ и другие секреты должны оставаться на сервере.

## Проверки и сборка

```powershell
npm.cmd run check
npm.cmd run build:web
npm.cmd run build:android:bundle
npx.cmd expo-doctor
```

Веб-сборка появляется в `dist`. Это SPA: при размещении настройте возврат `index.html` для неизвестных путей. Автоматической публикации сайта нет.

`build:android:bundle` проверяет сборку JavaScript для Android и создаёт `dist-android`; это не APK и не проверка на эмуляторе. Для `npm.cmd run android` нужен подключённый Android с инструментами SDK или настроенный эмулятор. Android Studio / SDK в стандартных каталогах на этом компьютере не обнаружены. Быстрый запуск через Expo Go не требует Android Studio. Локальная сборка iOS требует macOS и Xcode.
